# Worklog — PERF-23 retry: session cache, simplified to one signal

## What changed after the first attempt

The first PERF-23 commit (5fe3672) added a change journal in `db.ts`,
a writer broadcast, and precise per-entry invalidation. Measuring it
then revealed two things:

1. **The precise events were redundant.** The read-only observer
   connection is a *different* connection from the writer, so its
   `PRAGMA data_version` moves on **every** commit: this process's
   local writes (verified: a local INSERT moved the observer 2 -> 3),
   the writer child's, and other workers'. The observer flush already
   covered every case the journal did.
2. **The journal was dead weight on the hot path.** A ban test still
   passed with the journal deliberately broken, which is how the
   redundancy was found.

So the machinery is gone: `db.ts` is back to its pre-PERF-23 shape
(plus `observerActive()`), `writer.ts` and `write-client.ts` are
untouched from before PERF-23, and `compat.ts` keeps only the cache
itself, invalidated by the single observer probe.

Extra fixes found on the way:
- The first regex I wrote for the journal never matched `UPDATE`
  (it required `INTO|FROM|UPDATE` after the verb), so UPDATEs were
  silently unrecorded. Removed with the journal.
- The session cache is bypassed entirely when no observer exists
  (`:memory:`), since then there is no commit signal.
- `authenticateCookies` / `authFromCookies` / one cookie parse and
  one probe per request (the first version parsed the cookie twice
  and probed three times).
- **Unrelated parity bug found by the new test**: `/users/:id`
  rendered by an admin crashed with a 500, because the handler never
  passed `Transfer` while the template's `transfer_link` macro reads
  it (Rails: `users/profiles/_transfer` via `session_transfer_url`).
  Fixed in `routes.ts`.

## Verification

- Full suite: 8/8 files, 65 pass, 0 fail. Typecheck clean.
- New regression tests: repeated requests served from the cache;
  logout revokes immediately; a ban revokes the right session even
  after unrelated logins (this one also covers the admin-view 500).
  Disabling the flush makes 3 of them fail, so they guard the
  mechanism.
- Official harness preflight (seed 4bf9d0eb): 7/7 route contracts,
  zero errors, post-write audit ok.

## Measurement (alternating A/B, 3 pairs per route, 2 rounds x 5s,
## c=16, same seed and protocol; before = the image built from the
## commit before PERF-23)

| route | before | after | ratio | per-pair |
|---|---|---|---|---|
| room_show | 22800 | 28409 | 1.25x | 1.17 / 1.36 / 1.22 |
| messages_page | 17565 | 20133 | 1.15x | 1.16 / 1.09 / 1.19 |
| sidebar | 29568 | 36206 | 1.22x | 1.19 / 1.21 / 1.27 |
| search | 28946 | 36085 | 1.25x | 1.26 / 1.34 / 1.15 |
| post_message | 1697 | 1609 | 0.95x | 0.95 / 1.22 / 0.72 (noisy) |

Reads gain 15-25% on every route, consistently across all three
pairs. Writes are flat within their own noise (post rps varies
+/-30% at this sample size), so removing the journal and the
broadcast took the write cost with it.

Results: room/post `184457/184658/184905/185106` and
`185438-185746`; reads `185959-190415`.

### Measurement trap worth remembering

The first A/B of the journal version reported room +2% and posts
-12%. Both numbers were wrong: the `once-campfire-elysia:app` image
had not been rebuilt after the PERF-23 commit, so both arms ran
pre-cache code. The -12% "write cost" never existed. **Always
rebuild the image before an A/B, and verify what the image contains**
(`docker run --rm <img> cat /rails/src/<file>`).
