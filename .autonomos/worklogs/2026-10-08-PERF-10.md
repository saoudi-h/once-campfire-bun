# Worklog — PERF-10: single-writer IPC (ADR-001, accepted)

## What was done

Implemented the accepted ADR-001: dedicated writer child process
for attachment-less message POSTs (the ~99% write volume).

- `src/domain.ts`: extracted `insertMessage` (pre-sanitized insert)
  from `createMessage`; unchanged statements and semantics.
- `src/writer.ts` (new): unix-socket JSON-lines RPC server, own DB
  connection, executes `insertMessage`, maps error status (403/500).
  Runs only with `CAMPFIRE_WRITER=1` (`import.meta.main` guard).
- `src/write-client.ts` (new): worker-side channel with
  request/response correlation, reconnect loop, fail-loud 503 when
  down (no retry; `client_message_id` idempotency documented only).
- `src/server.ts`: master spawns/supervises the writer like HTTP
  workers; HTTP workers `connectWriter()`; single-process and tests
  keep local writes (no contention there).
- `src/routes.ts`: plain POSTs await the writer, fallback to local
  when unavailable; attachment posts keep the outer txn path.

Verified locally (2 workers): IPC post 200 with row persisted,
non-member redirect preserved. 53 tests pass (local fallback),
typecheck clean.

## Key decisions and why

- Writer in master-supervised child (not master itself): a write
  burst must not stall jobs claiming + fanout echo on master's loop.
- Single-process keeps local writes: no contention with one
  writer; keeps dev at 1 process and tests on the local path.
- No retry on writer failure: 503 loudly until supervision
  restarts it (same posture as worker crashes).
- Group-commit batching deferred to PERF-12 (backlog).
