# Worklog — AUDIT-03: proof hardening (tooling)

## What was done

Fixed four audit findings in the bench tooling (no re-bench; all
verified on existing JSON or synthetic data):

- `bin/bench-compare.sh`: the measured HTTP duration now honors
  `HTTP_SECS` instead of a hardcoded 8s. Warmup (4 conc, 2s) and the
  c=1 probe (5s) stay fixed by design.
- `bin/bench-compare.sh`: hard failure gate at the end of each rep.
  Any HTTP error, non-2xx status, or empty `ok`, any cable run with
  `ready != clients`, and any empty upload run now abort with
  `app rep N FAILED` instead of writing a silent partial JSON.
- `bin/bench-report.py`: the errors section covers all reps (was
  first rep only). Verified with synthetic data: a rep-1 fault amid
  clean reps is reported.
- `bin/bench-report.py`: new "Response sizes" section from the
  loadgen's `avg_bytes` (bytes on the wire, gzip negotiated). No
  advantage ratio: near-equal means like-for-like, a gap flags a
  non-equivalent comparison. On `bench/results/publish` it confirms
  room parity (24,280 vs 24,231) and flags sidebar (1,903 vs 5,910,
  pre-AUDIT-01 data), search (10,804 vs 9,766), avatar (4,004 vs
  3,368), and static CSS (1,218 vs 654) as needing like-for-like
  review before any publishable claim.
- `env.txt` now records bench parameters plus the Rust image's baked
  `GIT_REVISION`/`APP_VERSION`; README documents building both
  images with revision args (`REVISION` for Bun, `GIT_REVISION` for
  Rust). Note: the current `campfire-bun:bench` image predates this
  (label `revision=local`); it must be rebuilt with the arg before
  the next publishable run.

## Key decisions and why

- No re-bench in this pass: the fixes change tooling, not the app.
  A fresh 3-rep run is needed before publishing (also to refresh the
  sidebar numbers post-AUDIT-01 and rebuild the Bun image with its
  revision).
- Mixed multi-account load left out: the loadgen takes one cookie
  per `http` call, so interleaved multi-user load would be a new
  suite in the shell script, not a proof fix. Optional follow-up.
- `avg_bytes` is wire bytes under negotiated gzip, not decompressed
  bodies — labeled as such so CSS/avatar gaps are read correctly.
