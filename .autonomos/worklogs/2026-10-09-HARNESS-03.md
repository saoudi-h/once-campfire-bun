## Key decisions and why

- Publish via upstream PR (not a long-lived fork): the adapter is
  2 lines, the container contract is already satisfied by our
  Dockerfile, and official numbers require the shared harness.
  Review burden accepted as the cost of official status.
- Seed rebuilt before submission: the replica's mismatched VAPID
  would fail a strict reviewer even though it is bench-invisible.
- No code change: this task is seed + PR + docs only.

## Pitfalls worth keeping

- `bin/seed` aborts if the output exists: move `fixtures/default`
  aside first (kept as `.bak-bash-replica`).
- bin/seed needs ruby + docker CLI + the reference image; run it
  in bench-ruby:1 with the docker socket mounted (same pattern as
  compare.rb, minus --network host: the seed container runs
  locally).
- The push to the fork needs SSH (`git@github.com:...`): the gh
  token is configured for ssh git operations; the https remote
  fails with "could not read Username".
