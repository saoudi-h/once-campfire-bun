# Worklog — PERF-19: `bun build --compile` for production

## What was done

Made the single-file compile path work end to end and measured it
against the interpreted server. Adopting it in the Dockerfile is the
user's call; nothing in the default build changed.

### Fixes needed (in order)

1. **Data files** (`src/data.ts`, new): `templates/`,
   `assets/generated/`, `src/translations.json`, `src/schema.sql` are
   read by path and the bundler embeds none of them. `dataPath(...)`
   resolves `CAMPFIRE_DATA_DIR` or cwd first (where the binary runs),
   then the source tree, so dev/tests are unaffected.
2. **Writer role** (`src/server.ts`, `src/writer.ts`): the master
   spawned `writer.ts` as a script path; a compiled binary ignores
   argv and ran the full server as the "writer", which forked its own
   master forever (264 master processes observed). Fix: env dispatch
   at entry (`CAMPFIRE_WRITER=1` -> exported `runWriterCli()`), the
   `import.meta.main` trigger kept for the script path.
3. **First-boot race**: compiled children boot in milliseconds and
   two raced `schema.sql` creation ("webhooks missing id..."). The
   interpreted run never lost this race. The master now calls
   `initialize()` before spawning children.

### Verification (compiled binary, WEB_WORKERS=2)

- First boot on virgin DB, 2 runs: 0 restarts, 1 writer, /up 200,
  exactly 4 processes (master + 2 workers + writer).
- Renders `/first_run` (24KB, nunjucks + translations + manifest),
  serves digested assets, `/service-worker` and `/account/logo`
  (reference tree).
- Real write path through the writer IPC (loadgen login/scrape/POST):
  2433 rps, 9735 x 200, 0 errors, writer stable.

### Measured (3 runs each, seed copy, loadgen on /session/new, c=8, 5s)

| | boot | RSS | rps |
|---|---|---|---|
| interpreted | 105 / 106 / 103 ms | 75 / 75 / 75 MB | 5495 / 5574 / 5556 |
| compiled | 78 / 73 / 75 ms | 79 / 75 / 75 MB | 5409 / 5466 / 5460 |

Boot improves ~29% (median 105ms -> 75ms). RSS unchanged (~75MB).
Throughput within noise (-1.7%, runs vary ±1.5%).
`--minify` saves 2.48MB of bundle; RSS is dominated by the runtime.

## Key decisions and why

- Sharp stays a lazy import (PERF-18): the compiled binary must not
  touch libvips on boot. WebP/TIFF/GIF/AVIF still route to sharp.
- Dispatch by env, not argv: one entry, three roles (master/worker/
  writer). The checked-in spawn code still passes the script path for
  the interpreted mode; the binary ignores it.
- Not enabled in the Dockerfile: single-file compile ships without
  the data directory the app needs beside it (templates, assets,
  src/*.json, reference/). That layout change plus a bench compare
  before adopting.
