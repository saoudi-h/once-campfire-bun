# Worklog — PERF-12: group commit tried and reverted (negative result)

## What was done

Implemented backlog-draining group commit in the writer (up to 64
queued requests per transaction), first with nested SAVEPOINTs per
item, then with savepoint-free statements. Measured fresh-seed
post-16 runs:

| workers | single-txn writer | savepoint batch | plain batch |
|---|---|---|---|
| 1 | 2252 | — | 2296 |
| 2 | 4019 | 3775 | 3900 |
| 4 | 3954 | 3564 | 3850 |

No gain; the savepoint variant regressed ~10%. Reverted the code
fully (`git checkout`): the tree keeps zero trace, this worklog
keeps the lesson.

## Key decisions and why

- Group commit amortizes BEGIN/COMMIT, but with synchronous=NORMAL
  a commit costs ~15us against ~300us of statement work: nothing to
  amortize. It matters for fsync-bound (FULL) workloads, not ours.
- Worse, batching adds head-of-line delay: early responses wait for
  the batch's remaining work, while the serial writer gains no
  throughput (same statements, one loop).
- Lesson: don't batch a serial server with cheap commits. The
  writer stays one-transaction-per-message and immediate.
- A file-corrupting edit mishap mid-task (stray brace + merged
  signature line in `domain.ts`) was caught by typecheck; fixed by
  reading the exact region and rewriting the whole block. When an
  edit target has been edited before, re-read before editing.
