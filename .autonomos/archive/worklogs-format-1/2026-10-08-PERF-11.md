# Worklog — PERF-11: avatar/static-asset serving

## What was done

Avatar went through the full compat pipeline (cookie decrypt,
session/user/account lookups, variant JOIN, fs stats, file stream):
17.6k rps vs Rust 93k. Static assets streamed from disk per
request: 74k vs 108k.

- `public.ts`: new `avatarPayload()` (signed id is the credential,
  no session/DB auth); static SVGs read once; blob responses cached
  in memory keyed by user id (immutable bytes), dropped on avatar
  change (`replaceImage` User/avatar, avatar DELETE); ranges and SVG
  initials stay dynamic; errors -> 404 like before. Reuses `serve()`
  + `makeRes` (zero logic duplication).
- `app.ts`: native `/users/:userId/avatar` route (304 from stored
  etag with zero DB on hits); `/assets/*` served from a lazily
  filled memory map (digested names are immutable; tests only pay
  for what they touch). Compat avatar route removed.
- Verified: 200 webp + etag, 304 on match, 404 forged, HEAD routing
  unchanged (same Elysia GET registration as before).

Bench same host, 4 workers: avatar 17.6k -> 36k (native) -> 78k
(cached) vs Rust 93k (0.84x); css 74k -> 98k vs 108k (0.9x);
room re-checked 22-24k (an isolated 16.4k run was host noise).
53 tests pass, typecheck clean.
