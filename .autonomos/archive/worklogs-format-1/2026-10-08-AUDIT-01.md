# Worklog — AUDIT-01: sidebar parity fix

## What was done

An independent audit found the sidebar comparison indefensible:
we served a 7.7KB fragment with hardcoded `Placeholders: []`
while Rails/Rust serve a ~30KB page with suggested direct contacts.

- `domain.placeholderUsers`: ports
  `Users::SidebarsController#find_direct_placeholder_users`
  (active users outside shared directs, oldest first, max
  20 minus excluded). Verified byte-identical suggestion sets vs
  Rust on the seed (bender, deploy_bot, loner).
- `templates/pages.html`: new `sidebar_page` macro (layout +
  fragment). Plain GET renders the Rails-equivalent full page;
  Turbo-Frame requests keep the fragment path (the real browser
  flow is unchanged).
- Cache key extended with frame/page variant + placeholder
  versions. 53+1 tests pass (new placeholder parity test:
  exclusion, deactivation, ordering, cap, fragment forms),
  typecheck clean.

Fair re-measure, same host/method: Bun 19,575 vs Rust
16,963 rps (1.15x, was 1.58x on non-equivalent responses).
README corrected to the honest number.
