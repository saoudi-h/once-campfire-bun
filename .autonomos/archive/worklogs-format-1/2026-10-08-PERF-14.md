## Key decisions and why

- Reads are competitive at EVERY level (no single-config
  overfit): room Bun-ahead 1.07-1.23x from 1 to 8 threads;
  messages at parity (+/-10%). Post trails 0.67-0.75x at every
  level: same writer-lock story everywhere, not config-specific.
- Writes don't scale past ~2 workers on either side of the
  comparison: Bun post flattens at the single writer loop
  (~4000rps ceiling); more HTTP workers only add lock/format
  parallelism up to that ceiling.
- MEMORY is the honest gap on small servers: Bun idle grows
  ~40MB per worker (35/115/161/277MB) vs Rust flat 14-38MB;
  peak under POST blast 277->1185MB vs 92->155MB. Causes:
  per-process Bun runtime baseline + per-worker cache caps
  (4x32MB) x N workers + POST-created fragments filling every
  worker's store. -> PERF-15 (tunable caps) queued, default
  unchanged: small boxes should run fewer workers today.
- 8-thread flattening (both apps) is partly conc-8 starving 8
  server threads; comparative result still valid (same load).
